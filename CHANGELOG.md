# Changelog

### Security
- **Minimum `Pillow` and `pypdf` versions raised.** `Pillow>=12.3` (from `>=12.2`) and `pypdf>=6.14.2` (from `>=6.10.2`). Both read untrusted input — `pypdf` parses fetched PDFs, `Pillow` parses figure images — and the newer releases carry upstream parsing fixes.

## [0.6.0] — 2026-07-20

### Added
- **Markdown manuscripts (`.md`) get prose and structure checks.** `sciwrite-lint check paper.md` and `sciwrite-lint contributions paper.md` now parse the manuscript as markdown — splitting on headings into sections, abstract, and paragraphs — instead of treating it as LaTeX. Prose-quality, structure-promises, cross-section consistency, and full-paper consistency run on the markdown content. `.tex` and `.pdf` inputs are unaffected.
- **Citation checking for markdown manuscripts (pandoc `[@key]`).** `dangling-cite` now runs on markdown: pandoc-style `[@key]` citations are extracted via pandoc's own AST (deterministic and code-fence-safe — a `[@x]` inside a fenced code block is never miscounted) and matched against the manuscript's bibliography. The `.bib` is resolved the way pandoc resolves it: an explicitly configured `bib`, then the YAML `bibliography:` field (single file or a list), then the sibling `{name}.bib`. A document using numeric `[1]` citations, or one with no resolvable `.bib`, is reported with a warning rather than silently checked.
- **Full-pipeline reference verification for markdown.** Running the full pipeline on a markdown manuscript (`sciwrite-lint check --paper …` with a `.md` source) now extracts its cited references from the sibling `.bib`, narrows them to the citations actually present in the text, and runs the reference-verification stages (reference existence, retraction, metadata accuracy) — the same stages `.tex` and `.pdf` inputs use. Uncited bibliography entries are skipped, as for LaTeX.
- **Figure and cross-reference checks for markdown (pandoc-crossref).** `dangling-ref` and `unreferenced-figure` now run on markdown: pandoc-crossref references (`@fig:`, `@sec:`, `@tbl:`, `@eq:`, `@lst:`) are matched against the labels actually defined in the document (`{#fig:…}` figures, `{#sec:…}` headings, table ids), and a figure defined but never referenced is flagged. A reference like `@fig:flow` is correctly recognised as a cross-reference, not a bibliography citation, so it is no longer mistaken for a dangling citation. With this, every deterministic manuscript check supports markdown.
- **Claim verification reaches markdown citations.** The claim-verification stage now builds its per-citation claim contexts from a markdown manuscript's pandoc `[@key]` citations (the prose around each citation), so cited sources with available full text are checked for claim support — the same path `.tex` and `.pdf` use.
- **Footnote-URL web sources for markdown.** Markdown footnotes (`[^id]` or inline `^[…]`) that carry a `<url>` / `[text](url)` link are now matched against archived web captures and tracked as references — the same treatment LaTeX `\footnote{\url{}}` gets, including binding the footnote's host sentence to a verifiable claim for claim-support.
- **Empty manuscripts say so.** A run that finds zero references now reports a `no-references` notice instead of a silent clean-looking report — usually a sign the bibliography wasn't detected rather than a genuinely citation-free manuscript.
- **`init` and `ref-health` support markdown.** `sciwrite-lint init` now scaffolds markdown manuscripts (a `.md` file with a sibling `{name}.bib`; ordinary markdown like `README.md` is left alone). `sciwrite-lint ref-health` accepts markdown: it reports cite/bib mismatches (a `[@key]` with no `.bib` entry, a `.bib` entry never cited), ID coverage, and entry-type breakdown — the same fast, no-API report it gives for LaTeX.
- **`ref-health` also supports PDF.** Reference health now runs on `.pdf` manuscripts too, sourcing references from GROBID (a local parser, so still no external/network APIs — the GROBID container must be running).
- **Unreferenced-figure detection for PDF.** `unreferenced-figure` now runs on `.pdf` manuscripts: each figure GROBID numbered (via its caption label) is checked against the `Figure N` mentions in the prose, flagging any figure the text never points to. Only cleanly-labelled figures are considered, so GROBID's mis-detected figures don't cause false positives.
- **`sciwrite-lint init <file>` registers a specific manuscript** — including a PDF (`sciwrite-lint init paper.pdf`). With no argument, `init` auto-detects a single `.tex`/`.md` manuscript as before; when it finds **several**, it now lists them and asks you to name one rather than registering all (you rarely want every `.tex` in the tree). PDFs are only registered when named explicitly — there's no signal separating a manuscript PDF from a project's reference/figure PDFs.
- **`download_pdf` can skip the title-match gate (`require_title_match=False`).** The public `download_pdf` normally validates every fetched PDF against the bibliographic details you pass (title / authors / DOI / year) — a multi-signal content check that relies on the GROBID container. The new `require_title_match=False` argument skips that gate: any well-formed PDF (`%PDF` magic bytes and a non-trivial size) is accepted from the first source that returns one, with no GROBID required. It's for callers who already trust the identifier — for example one resolved from a search hit — and don't need the title re-checked. The download's SSRF and size-limit safeguards are unchanged, and `DownloadResult.title_check_score` is left unset when the gate is skipped.
- **Generate a synthetic cross-format manuscript corpus.** `python -m evals synth-corpus --out DIR` writes a small set of manuscripts — each demonstrating one issue sciwrite-lint detects (dangling citations, unreferenced figures, dangling cross-references, prose errors, percentages that don't add up, footnote URLs, uncited bibliography entries, numeric `[1]` citations, multi-file bibliographies), plus clean controls — in LaTeX and Markdown, and PDF with `--format tex,md,pdf`. A `MANIFEST.md` lists what each scenario should trigger, so you can synthesize and lint them yourself. Two coverage evals run the checks on the rendered corpus: `python -m evals eval-synth-corpus` reports which deterministic checks survive a round-trip through PDF rendering and GROBID, and `python -m evals eval-synth-corpus --llm` reports the LLM-backed checks on the text formats — making cross-format detection coverage visible.

### Changed
- **Unsupported manuscript types are now rejected with a clear error.** A manuscript path whose extension is not `.tex`, `.pdf`, or `.md` (e.g. `paper.docx`) previously fell through to the LaTeX parser and produced degraded output; it now fails immediately with `Unsupported manuscript type: … Supported formats: .tex, .pdf, .md` and a non-zero exit code, at both the `check` and `contributions` entry points.

### Fixed
- **`download_pdf`'s `DownloadResult.title_check_score` is now populated.** The field existed but always returned `None` — the match validator computed a title-similarity score, then discarded it before it reached the result. It now carries the score when the title-match gate runs (low or `0.0` when a download was accepted on a non-title signal such as a DOI match), and stays `None` only when there was no title comparison to report: the gate was skipped (`require_title_match=False`), or only an identifier was supplied.
- **Local-only checks make no reference-database network calls at all.** Reference verification used to run on every `check`, so a run selecting only local checks (e.g. `--checks claim-support`) probed OpenAlex in preflight (blocking the run when OpenAlex was unreachable or rate-limited) and then called OpenAlex/Semantic Scholar/CrossRef during the run — even though those checks verify against local sources and the local model. Now a single rule (`run_uses_reference_db`) governs all of it: the preflight OpenAlex probe, the reference-verification stage, and the depth-2 bibliography stage each run **only** when a reference-database check (reference existence, accuracy, retraction, reliability) is enabled. A `--checks claim-support` run is therefore never gated on, and never calls, the reference APIs — consistent with the standalone `verify-claims` command, and it verifies against local + already-cached sources. (Run a full `check` to also fetch and verify open-access full text.) When those APIs *are* used, the probe now distinguishes rate-limiting (HTTP 429/503, reported as "rate-limited") from genuine unreachability, and OpenAlex requests carry the contact email so they use the polite pool's higher shared limit.
- **`verify-claims` verifies against locally-archived sources without a prior `check`.** The standalone command skipped the source-preparation stages, so it reported "0 have local source" even when `.md`/PDF snapshots were present in the paper's sources folder. It now ingests matching drop-folder sources and builds their retrieval index up front — locally, with no network downloads — so claims are verified against archived snapshots offline.
- **Claim verification now resolves for markdown manuscripts with multi-section cited sources.** When the manuscript itself was markdown (`.md`), the per-citation query vectors used to retrieve relevant passages from a cited source were never pre-computed — the manuscript's citation contexts weren't persisted, so the embed stage had nothing to encode. Every cited source long enough to need retrieval (more than a handful of sections) then returned `CANNOT_DETERMINE`, even when its full text was available and indexed. Markdown manuscripts now persist their citation contexts the same way `.tex` and `.pdf` do, so those query vectors are built and claims are verified against the cited text. (Short sources were unaffected, since they skip retrieval.) The accompanying diagnostic was also misleading — it reported "No embeddings" when the cited source's embeddings were in fact present; it now distinguishes a missing semantic index from a missing query vector from an embedding-model change.
- **Academic `.md` summaries are now indexed, so claim verification works on long ones.** A markdown summary dropped in a paper's academic sources folder was only usable for claim support when it was short (≤5 sections); longer summaries returned `CANNOT_DETERMINE` because the semantic index was built for PDFs and web captures but never for academic `.md` summaries. They are now embedded the same way, so claims are verified against them regardless of length. (Web captures and PDFs were already indexed; only academic `.md` summaries were affected.)
- **`--checks` now actually skips the cited-paper consistency stage instead of running it and throwing the results away.** When a run was narrowed with `--checks` (e.g. `--checks claim-support`), or checks were turned off via `[rules] disable` in config, the internal-consistency checks on cited papers — cross-section consistency, structure promises, and full-paper consistency — still executed their LLM calls and only discarded the findings afterwards. That was wasted compute on every run, and the large full-paper prompts could exhaust the read timeout and abort the whole run. These checks are now governed by the same enable/disable filter as every other check: an individually disabled check is never queried, and when all of them are disabled the stage is skipped outright (no per-reference setup, no LLM work). Contribution scoring is unaffected.
- **Gemma-3 models now start instead of timing out.** Every vLLM model was launched with an fp8 KV cache, which gemma-3's attention does not support — the engine crash-looped at startup, the container never became ready, and the run failed only after the readiness timeout. The KV-cache dtype and CUDA-graph capture are now chosen per model: gemma-3 uses an auto KV cache with eager execution, while the other models keep the fp8 KV cache and CUDA graphs unchanged. `verify-claims --model gemma3` and the containerized gemma-3 profile now come up normally.

## [0.5.1] — 2026-05-29

### Fixed
- **Manuscripts converted to LaTeX by pandoc no longer fail to parse.** `.tex` generated by pandoc (e.g. from a Markdown manuscript) wraps each heading in a `\hypertarget` anchor that could previously abort the parse; these are now unwrapped automatically. Hand-written LaTeX is unaffected.

## [0.5.0] — 2026-05-24

### Added
- **Per-prompt cache for manuscript-LLM checks.** Prose-quality, cross-section consistency, full-paper consistency, structure-promises, and internal-consistency-pairs now memoize each LLM call. A clean rerun against unchanged prose dispatches zero LLM calls; editing one sentence re-pays only for that sentence (and any sibling whose surrounding paragraph context shifted), so iterative edit→rerun loops on long manuscripts stay cheap. Switching the local vLLM model forces a full re-check.

### Removed
- **`verify-claims --backend claude` removed.** The Claude Sonnet path on `verify-claims` is gone; the `--backend` flag is removed and claim verification now runs only against the local vLLM. Existing workspaces auto-invalidate any cached Claude-stamped verdicts on the next run — no `--fresh` or migration step needed.

### Fixed
- **GROBID error messages now point at the log command.** Transport, response, and header-extraction errors from GROBID now suggest `Check container logs: sciwrite-lint containers logs grobid` so the operator's next step is in the message itself. PDF-classification subprocess failures (`pdftotext` / `pdfinfo`) are now logged at debug instead of silently swallowed.
- **Claim verdicts no longer leak across edits or model swaps.** The `verify-claims` cache used to reuse a prior verdict whenever a citation matched by key and line, even after the inputs had changed. Re-runs now invalidate when (a) the prose around the citation was edited, (b) the local vLLM model changed, (c) the cited source kind changed (summary upgraded to a real PDF, web page to a PDF), (d) the source file was overwritten, or (e) the cited PDF was re-fetched. Existing workspaces self-correct on the next run; no `--fresh` needed.

### Documentation
- **Iterative editing without `--fresh`.** New README subsection "Iterative editing — no `--fresh` needed" documents the cache contract: every cache layer (source ingest, parsing, embeddings, vision figure descriptions, cited-paper checks, manuscript-LLM checks, claim verification) invalidates from a hash pinned to its inputs, so editing one sentence, replacing a figure, swapping the local LLM model, or replacing/re-fetching a cited PDF all recompute only what's affected. `--fresh` is reserved for the rare wipe-workspace case; a stale-looking result is a bug to report, not a workflow problem.

## [0.4.0] — 2026-05-19

### Added
- **Operational diagnostics separated from manuscript findings.** `check_*.json` and the terminal output now split into `findings` (manuscript issues) and `system_issues` (linter operational state — skipped checks, incomplete vision runs, internal errors, parse failures). `total_findings`, `errors`, `warnings`, and the SciLint Score reflect manuscript quality only; operational state is summarized in `total_system_issues` and rendered as a separate panel. New diagnostic rule_ids: `llm-unavailable`, `vision-incomplete`, `internal-error`, `parse-failed`.
- **Every inline citation now has a row in `claim_results`.** Cites the verifier never reaches (no local source, `--key` filter, `--limit` truncated the batch) get `verdict='SKIPPED'` with a structured `skip_reason`, making the table the single source of truth for what happened to each cite. SKIPPED rows are excluded from scoring and finding emission so unverifiable cites don't dilute reliability averages or produce false "no purpose" warnings.
- **Claim coverage line in the CLI integrity summary.** After the SciLint Score banner, runs now print `Claim coverage: N verified, N undetermined, N skipped (no local source)` so reviewers can tell at a glance which slice of the bibliography actually got LLM-checked.
- **`manuscript_citations` table in `workspace.db`.** One row per inline citation occurrence (`ref_key`, `line`, `section`, `context`, `source_type`, `source_hash`). Makes inline citations a first-class queryable artifact for tooling that inspects `workspace.db`.
- **`[vision] subprocess_per_image_timeout` TOML knob.** Per-image wall-clock budget for the cited-vision subprocess. Default raised from 5s to 10s/image.
- **Split client- vs server-side concurrency knobs.** Two distinct fields each for text and vision:
  - **`[llm] max_concurrency` / `[vision] max_concurrency`** (client side, defaults `256` / `128`) — controller `upper_bound` under the dynamic regime, raw `asyncio.Semaphore` cap under the static regime. Auto-clamped to safe ceilings when `dynamic_concurrency = false` (see the static-mode auto-clamp entry below).
  - **`[llm] server_max_seqs` / `[vision] server_max_seqs`** (server side, defaults `256` / `128`) — passed to the corresponding vLLM container as `--max-num-seqs` (admission ceiling, baked at `podman run` time). Independent from the client cap.
  Setting client higher than server is a misconfiguration rather than a hard error — the dynamic controller self-corrects on `requests_waiting > 0`, and in static mode the surplus queues at the vLLM API surface (suboptimal under sustained load). Server-side slack is harmless either way. Splitting the fields makes the distinction explicit and lets operators raise the server ceiling without growing the client semaphore (or vice versa). See [docs/services.md](docs/services.md).
- **`[containers] grobid_max_concurrency` TOML knob.** How many PDFs to send to GROBID in parallel (default `4`). Raise together with `[containers] grobid_memory` — rule of thumb: 2–3 GB per slot for typical PDFs, more for book-length scans.
- **Embedder load-time VRAM budget check.** A WARNING fires if the embedder's estimated peak VRAM exceeds 85 % of free CUDA memory at load time, naming the offending knobs and the suggested fix — so swapping to a model that won't fit is caught at load time instead of as a surprise OOM mid-pipeline. Override the budget with `SCIWRITE_EMBED_VRAM_BUDGET_GB` for unusual hardware.
- **Embedder panel in `sciwrite-lint containers monitor`.** Surfaces the embedder subprocess (which lives outside `podman ps`) — model name, batch size, and estimated peak VRAM vs the post-swap budget for the configured GPU. Yellow-highlights the peak when it exceeds budget.
- **`[vision] dynamic_concurrency` flag (default `true`).** The admission cap for vLLM call sites is decided at runtime by a controller that polls vLLM's `/metrics` and resizes itself based on observed KV-cache utilization and queue depth, instead of a single static value. Applies to vision figure description, text LLM checks (manuscript / ref-internal), and claim verification (vLLM backend); `[llm] max_concurrency` and `[vision] max_concurrency` become the controller's hard upper bounds rather than working points. Tunable via `[concurrency] target_kv_lo` (default `0.60`), `target_kv_grow` (`0.70`), and `target_kv_hi` (`0.80`), which define the dead band around vLLM's preemption zone. Each tick is persisted to a local cache so subsequent runs warm-start from what the previous run discovered, rather than crawling up from the conservative default every time. Opt out with `[vision] dynamic_concurrency = false` to restore the static `asyncio.Semaphore` path (e.g. for debugging the controller itself or pinning a single cap for reproducible benchmarks).
- **Static-mode concurrency cap auto-clamp.** When `dynamic_concurrency = false` is set, `[llm] max_concurrency` and `[vision] max_concurrency` are automatically clamped to safe ceilings (32 for text, 16 for vision) — and a WARN is logged if a higher value was configured. Rationale: without the controller's gradual ramp, a raw `asyncio.Semaphore` driving vLLM at high N triggers API-server connection bursts (~35 % soft-fail observed at static cap=128 on a 300-image cache-cold workload). The two regimes have different safe ceilings, so the package-level defaults (text `256`, vision `128`) — sized for the controller-throttled case — are clamped at construction time when the operator opts out. Override by also lowering the cap below the ceiling (e.g. `[llm] max_concurrency = 16`).
- **Controller state in `sciwrite-lint vllm monitor`.** Each vLLM panel now shows a `Controller` row with current cap, in-flight count, last decision reason, and a 5-step cap trend, so the operator can see what the controller is doing without grepping logs.
- **`sciwrite-lint vllm start` / `containers start --replace` flag, with refuse-by-default for vLLM coexistence.** Starting a vLLM while another model's container is already running used to succeed silently and leave both processes fighting for VRAM — each launches with `--gpu-memory-utilization 0.85`, so the second one scales down to whatever's free at startup and both end up with crippled KV cache budgets (preemptions, slow inference). `start_container` now refuses by default and prints how to recover. Pass `--replace` to have the conflicting container stopped first; idempotent reruns of an already-running model still no-op. The pipeline's text↔vision swap path is unaffected — it already stops competitors explicitly before starting the target.

### Improved
- **Wire-side JSON schema length constraints removed (xgrammar fast path).** vLLM's constrained-decoding backend slows ~3× when a JSON schema carries `maxLength` / `maxItems` / `pattern` — a single `maxLength` on one field collapsed throughput from 30/30 success to 0/30 timeout at concurrency=60 in benchmarking. The generous-cap `Field(max_length=...)` constraints introduced in 0.2.x are now stripped from the wire schema; Pydantic still validates the decoded JSON post-response, and length guidance is inlined in prompts instead. Applied to every text and vision response schema.
- **Embed stage ~7× faster on cache-cold runs.** Combination of SDPA attention (O(N) memory instead of O(N²)), bf16 weights on CUDA-capable GPUs (cosine ≥ 0.9998 vs fp32), per-key bulk DB inserts, and embedder pre-warming during GROBID parse. A typical 60-key paper drops from minutes to under a minute.
- **GROBID transport hardened.** Per-PDF retries now cover the full transient set (429 / 500-504 plus `httpx.TimeoutException` / `ConnectError`) with exponential backoff, instead of crashing the parse stage on a single read timeout. The HTTP timeout itself now scales with file size — `clamp(60 + 10 × size_mb, 60, 600)` — so book-length scans finish instead of tipping the old 60-second ceiling. Per-key error isolation widened so one pathological PDF doesn't take down the batch.
- **Default `[containers] grobid_memory` raised from `8g` to `12g`** to give 4-slot parallel parsing enough JVM heap headroom (rule of thumb: ~3 GB per slot; 8 GB tipped the in-process throttle into kicking in at 70 % usage on real-corpus runs). Run `sciwrite-lint containers restart --recreate` so the existing GROBID container picks up the new limit (live `--memory` change isn't possible).
- **Text-LLM `max_tokens` raised from 2048 to 4096** to stop full-paper consistency checks hitting `finish_reason=length` and walking the thinking-budget ladder on every retry (medium → low → off, ~30-60 s per affected call). The structured-output budget doc already used 4096 in its calculations; the runtime config now matches.
- **Verify-claim ladder retrieval is per-level granularity-scoped.** L1 (sentence) and L2 (paragraph) candidate retrievals each run their own KNN scoped to that granularity, so each level retrieves the genuine top-N from its own population — previously a mixed-granularity KNN let denser sentence chunks dominate L2's ranking too, starving L2 of paragraph candidates. `ladder_top_n_paragraph` default raised from 5 to 10 to match L1's fan-out width (configurable via `[llm.ladder] top_n_paragraph`).
- **Cited-figure VL inference saturates the configured cap.** Image preprocessing was previously blocking the asyncio event loop, throttling vision-vLLM to ~5 concurrent requests regardless of the configured ceiling; preprocessing now happens off the loop, and cited figures dispatch as one cross-ref batch.
- **Dynamic concurrency benchmark.** On a 300-image cache-cold workload at vLLM cap=128: a static client cap completed 194/300 in 638 s with 106 soft-fails; the dynamic controller completed 299/300 in 473 s with 1 soft-fail. ~26 % faster wall time and ~100× fewer soft-fails on the same workload — static caps cannot adapt as vLLM's API server falls over under sustained connection bursts, while the controller's gradual ramp + adaptive shrink avoids it.

### Fixed
- **DOI-only PDF matches no longer auto-accept.** A DOI in the first two pages used to short-circuit validation, so a hallucinated bib wrapped around a real-but-wrong DOI could silently land the wrong paper in the workspace. Validation now requires a corroborating signal (title similarity, bib-author surname, or year). Bibs that supply only a DOI still accept on DOI alone. Run `--fresh` once to re-validate cached PDFs.
- **Long `check` runs no longer abort with `APITimeoutError` after dozens of successful vLLM calls.** A single request waiting too long for an admission slot used to cross the read timeout and kill the entire run, even with hundreds of completed peers. The text path now caps in-flight requests via `[llm] max_concurrency` and retries transient HTTP errors (timeouts, connection errors, 5xx, 429) under the existing retry budget.
- **Cited-vision subprocess no longer crashes mid-run on per-image transient failures.** Timeouts, connection errors, `httpx.ReadError`, and 5xx/429 responses now soft-fail to an empty description rather than aborting the batch and losing every in-flight peer. The catch covers the full `httpx.RequestError` hierarchy. Concurrency is also capped via `[vision] max_concurrency` for backpressure.
- **Embedding subprocess no longer crashes with `OSError: Argument list too long`** on papers with many claims. Claim contexts now flow through `workspace.db.manuscript_citations` instead of being JSON-serialized into the subprocess's `-c` argument.
- **`\citeunverified` is now normalized to `[CITE]` in claim contexts.** The cite-cleanup regex previously missed the `unverified` variant, leaking raw `\citeunverified{...}` markers into context text. The standalone and full-pipeline paths produced different context hashes for the same paper and missed the query-vector cache. A single shared regex now handles every variant (`\cite`, `\citep`, `\citet`, `\citeyearpar`, `\citeunverified`).
- **Crashes during context-build or inside a check surface as `internal-error` system issues** instead of being silently swallowed or polluting manuscript findings under the affected check's `rule_id` (where they counted toward `total_findings` even though the check hadn't run).
- **SciLint Score no longer drifts when the linter has a bad LLM/vision run.** Operational findings used to inflate the score's denominator without affecting the numerator. They now flow through `system_issues` and never reach scoring; the manuscript score reflects manuscript quality only. The same fix lands in per-rule TP/FP aggregation in the real-world pipeline eval.
- **Partial-content + length-truncation completions are now treated as failures.** vLLM's constrained-JSON decoder emitting partial JSON before hitting `max_tokens` used to be returned as if successful, then re-retried at a different layer. Both layers now share one retry budget, and the `thinking`-budget ladder steps down fully (high → medium → low → off) on truncation instead of wasting a retry attempt on the same-prompt backoff branch.
- **vLLM error count and visible warnings now match.** A run could report 144 errors with only 7 warning-level events because most 5xx/429 responses were logged at DEBUG. Transient errors are now retried under budget; non-transient errors log at WARNING; successful retries log a recovery line at INFO.
- **Refs and cited papers skipped or failed during the run are now reported by key** at the appropriate WARNING/INFO level instead of being DEBUG-only. The cited-vision summary log also distinguishes cache hits from new inference and reports retry success counts, so a slow run can be diagnosed from the log alone.
- **`claim_results` schema migration adds `resolved_at` and `evidence_locator` to pre-existing workspace DBs.** The earlier escalation-ladder schema change landed the columns in the `CREATE TABLE` definition but did not extend the migration's `ALTER TABLE` list, so existing DBs rejected `INSERT`s with the new columns and claim-verification verdicts could not persist. Existing workspaces now upgrade in-place on first DB open; no `--fresh` required.

## [0.3.0] — 2026-04-28

### Added
- **Public Python API for open-access acquisition.** `download_pdf`, `fetch_web`, and `search_by_title` are importable from `sciwrite_lint`, giving scripts and reference managers direct access to the OA chain without running the linter. See [docs/python-api.md](docs/python-api.md).
- **Six more open-access sources.** The full-text downloader now also searches NBER (US economics), RePEc/IDEAS (European and non-US economics), HAL (French national archive), ERIC (US education), NASA ADS (astronomy), and OSF Preprints (SocArXiv, PsyArXiv, ChemRxiv). Useful for papers whose OA copy lives in a discipline-specific repository rather than arXiv or the journal's OA tier.
- **NASA ADS API key.** Configure with `sciwrite-lint config set-key nasa-ads <TOKEN>` (free token at https://ui.adsabs.harvard.edu/user/settings/token). Without a key the source is skipped with a one-time notice.
- **`prose-quality` check.** Grammar and semantic word-choice review at sentence level — flags syntactic errors and wrong-word slips that style checkers miss (e.g. "comprise of" → "consist of"). Hedged language, passive voice, and stylistic preference are deliberately not flagged.
- **`sciwrite-lint check --checks ID[,ID...]` flag.** Run a comma-separated subset of checks instead of disabling every other one in `.sciwrite-lint.toml`. Unknown IDs fail loudly with exit code 2.
- **Local web captures and MHTML archives.** A new `local_web_dir` drop folder accepts `.md` summaries and `.mhtml` browser saves; ingest converts MHTML to markdown via trafilatura. Lets reference material from JavaScript-heavy pages participate in claim verification. See [docs/local-sources.md](docs/local-sources.md).
- **Footnote-URL claims are now verified.** Claims backed by `\footnote{\url{...}}` rather than `\cite{key}` are matched against `local_web_dir` archives and verified against the captured text — same SUPPORTS / NOT_SUPPORTED / CANNOT_DETERMINE verdict as cited references. URLs without a capture are skipped silently. LaTeX-only for now.
- **Hash-aware re-ingest of drop-folder sources.** Replacing a PDF or MHTML in `local_pdfs_dir` / `local_web_dir` under the same filename now triggers a fresh copy + GROBID re-parse on the next run. Previously you had to use `--fresh` or delete the workspace file.
- **Per-paper `local_pdfs_dir`.** Each paper can supply its own curated-PDF directory in its `[[papers]]` TOML block; otherwise auto-detected from `Sources/full_text/` next to `file_path`.
- **Pre-download candidate ranking for title-search OA sources.** NBER / RePEc / HAL / ERIC / NASA ADS / OSF now compare every plausible candidate to the bib evidence (title similarity + surname overlap + year) and pick the best — or reject all of them — before any bytes are downloaded.
- **Server-side author filtering** on HAL, NASA ADS, and ERIC. NBER, IDEAS, and OSF use the surname as a free-text ranking hint where no field filter is documented.
- **Self-consistency voting infrastructure for LLM checks.** `local-llm` checks can opt in via an `n_samples` attribute; the batch runner forwards it to vLLM as the OpenAI `n` parameter. `prose-quality` ships at `n_samples=1`; flipping to 3 turns voting on as a one-line change.
- **Per-check temperature for LLM checks.** Categorical judgments (`prose-quality`) run at `temperature=0.0` for reproducibility; voting regimes get `~0.3` for sample diversity. Other checks remain at the default 0.6.
- **Pandoc-based LaTeX cleaning at manuscript ingest.** Citations become `[CITE]`, cross-references `[REF]`, math renders as readable Unicode, and stranded punctuation from removed references is cleaned up before LLM checks see it. `pypandoc-binary` ships pandoc inside the wheel — no system-level pandoc install required.
- **`search_by_title` returns richer per-hit metadata.** The public API now populates `title`, `authors`, and `year` per hit (when the source exposes them) and returns every candidate per source rather than the first hit.
- **Typed exceptions for Python-API consumers.** `SciWriteLintError` and `LLMConnectionError` let agents catch specific error classes instead of matching `RuntimeError` strings.
- **Standard 0/1/2 exit codes.** Matching `ruff` / `mypy`: `0` clean, `1` findings at error level, `2` tool error. Previously a dead vLLM could exit `0` with empty findings.

### Improved
- **Uncited `.bib` entries are no longer verified or fetched.** The working set is now filtered to keys actually referenced from `\cite*` / `\nocite` (or `.aux` if compiled). Users with a shared lab-wide `references.bib` should see noticeably fewer API calls. `dangling-cite` still reports structural issues from the raw bib.
- **Vision-vLLM container no longer restarts on reruns when figures haven't changed.** Pre-flight probes now hash exactly the figures they would process, including TikZ rendered from the compiled PDF. Removes ~2–3 minutes of container-restart overhead per rerun.
- **Unavailable references no longer re-queried on every run.** Definitive negatives (every OA source reached and reported no match) are cached with a timestamp and skipped on subsequent runs. Cache lifetime configurable via `[api] fetch_retry_ttl_days` (default 30); transient failures still retry; `--fresh` bypasses.

### Fixed
- **Web-resource references are no longer reported as dead unless the server positively confirms the URL is gone.** Only HTTP 404/410 → "dead" (ERROR); 4xx refusals, 5xx, TLS / timeout / decoding errors → "blocked" (WARNING — manual verify). The verifier also sends browser-like headers to bypass mainstream WAF refusals. Run `sciwrite-lint check --paper <name> --fresh` once to re-classify existing workspaces.
- **Multi-signal PDF match validation replaces the single-title check.** Fetched PDFs are validated against title similarity + first-page surname / DOI / year + ERIC / CORE landing-page detection. Run `--fresh` once to re-validate cached PDFs.
- **Short generic titles no longer false-accept the wrong paper.** When the bib lists authors, the validator now requires at least one bib surname on the PDF's first two pages before accepting on title similarity alone.
- **Unicode / non-English titles no longer mangled in Solr queries.** Titles sent to HAL, ERIC, and NASA ADS now pass through a Solr-reserved-character escape that leaves every Unicode code point untouched. French, German, Chinese, Vietnamese, and Cyrillic titles are now queried as written.
- **Local PDFs can now be matched by citekey prefix.** Filenames starting with a known bib key (e.g. `smith2020_Paper_Title.pdf`) match by the citekey directly. Fixes a length-bias for short bib titles under the `{citekey}_{Title}.pdf` archival convention.
- **Manual tier overrides no longer get re-verified on every run.** `api_match="manual"` (set by `sciwrite-lint override`) and the new synthetic footnote-URL citations now short-circuit via the verify cache, matching the CLI help.
- **Book-length references no longer hit a hardcoded 300-second embedding timeout.** The timeout now scales with input size — short docs still get the 300s floor; long policy reviews and books get up to 4500s.
- **Full-paper consistency checks no longer stall on thinking-budget overruns.** `llm_query` now adds the active thinking budget on top of `max_tokens` instead of cannibalizing it; on `finish_reason=length` the retry steps thinking down (high → medium → low → off) instead of repeating the same doomed call.
- **TikZ-only manuscripts no longer crash the vision stage when `vision_backend = "vllm"`.** The pre-flight check now detects TikZ / vector figure environments and triggers the container swap.
- **Cited-reference vision stage no longer crashes with `asyncio.run() cannot be called from a running event loop`.** Cited vision now runs in a subprocess, isolating both `transformers` (CUDA) and vLLM (asyncio) cleanly.
- **Configured `vision_backend` is never silently downgraded.** The cited-vision subprocess path now honors the `vision_backend` setting end-to-end.
- **Downloads from servers that gzip binary content** (e.g. MPRA working-paper PDFs returning `Content-Encoding: gzip` for already-compressed files) now decode correctly.
- **`sciwrite-lint vision` exits `2` on tool failure** instead of `1`, matching the 0/1/2 convention.
- **Standalone `verify`, `status`, `fetch`, and `verify-claims`** now find local reference PDFs in the per-paper workspace; previously these commands scanned the top-level `references/` directory and missed already-downloaded PDFs. The full `check` pipeline was unaffected.
- **`sciwrite-lint verify-claims`** now computes claim-query embeddings on demand when run standalone — previously returned `CANNOT_DETERMINE` for every claim.
- **`python -m evals eval-real-world`** auto-discovers `.sciwrite-lint.toml` and preflight-checks the email config, instead of failing 10 minutes in.
- **Unparseable cited PDFs no longer abort the whole paper's fetch.** A bad PDF is now rejected individually; the OA chain tries the next source and the rest of the paper's references keep processing. The classified reason ("image-only PDF", "unsupported PDF producer", etc.) appears per reference in `verify` output and `check --format json`.

### Added
- **Higher-quality vision option.** Choose between the default Qwen3-VL-2B model and a larger Qwen3-VL-8B (FP8, via vLLM) for figure analysis. Select via `--vision-backend` or the `[vision]` section of `.sciwrite-lint.toml`.

- **GPU embeddings on native Linux** *(preliminary)*: embeddings run on GPU automatically when available.

### Changed
- **Faster end-to-end runs.** Vision processing now runs concurrently, claim-verification query embeddings are pre-computed, and redundant container swaps are avoided.
- **Consistency checks return a curated shortlist.** `full-paper-consistency` reports up to 5 findings per check and `cross-section-consistency` up to 4, ranked by the model. Papers with few issues are unchanged; papers with many issues now get the most important ones instead of an unbounded list.
- **Figure readability issues are itemized.** Each problem with a figure is reported as its own bullet instead of one combined note, so downstream consistency checks see one issue at a time.

### Reliability
- **Long-paper consistency analysis is now robust under heavy finding load.** Results from consistency and full-paper checks are always well-formed, even when the model identifies many issues in a single pass.
